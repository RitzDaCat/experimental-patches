## What the patch does

`DrmNamed1DLut::transferFunctionScale()` replaces the hardcoded PQ-125 selection:

- Bypassable named curves (bridged to the UAPI convention by the driver's implicit
  degamma multiplier) stay at 125.
- Mandatory fixed stages — constructed with `bypass == nullptr` when the DRM
  colorop exposes no BYPASS property (`drm_colorop.cpp:1394`, consumed at
  `:1437`) — follow `KWIN_DRM_NVIDIA_CSC_PQ_SCALE`, read once into a magic
  static: exact `"1"` → 1.0, anything else → 125 (the UAPI assumption).

All four scaling call sites (`inputScaling`, `outputScaling`, `bypassScaling`,
`bypassOutputScaling`) route through the helper; the stray free function
`namedTransferFunctionScale()` is removed.

## Strengths

- **Fail-safe default.** Absent or malformed env → 125, so stock patch-0016
  behavior and rollback safety are preserved. A wrong guess cannot silently
  pass; it can only be resolved by the controlled live test.
- **Correct discrimination point.** `m_bypass` nullability is exactly the
  mandatory-vs-bypassable distinction in the probed NVIDIA Full graph.
- **Fitting and programming move together.** The selected scale flows into the
  `Scaling` structs that feed the pipeline-fitting cache, so the fitted
  compensation and the programmed hardware stage share one convention.
- **Zero hot-path cost.** One env read at first pipeline fit, then cached. No
  per-frame work added. The latency payoff is indirect but real: if the
  hardware follows the internal 1.0 convention, resolving the current wrong
  assumption (offline harness: mean linear error 73–95 nits, ~322k domain
  clamps per grid) re-enables the direct-scanout path for SDR-on-HDR instead
  of forcing the compositor fallback.

## Findings

### 1. Silent fallback on unrecognized env values — BLOCKER

`value == "1"` else 125. A typo'd value (`"1.0"`, `" 1"`, quoted `"125"`)
yields 125 with no log output. The entire purpose of this knob is a one-shot
controlled experiment; an unrecognized value invalidates the run and could be
misread as "assumption matches hardware."

**Fix:** accept `"1"` and `"125"` explicitly; emit
`qCWarning(KWIN_DRM, ...)` when the variable is set to anything else. Unset
must stay silent.

### 2. Blast radius exceeds the NVIDIA CSC stages — NIT

The helper keys off `m_bypass == nullptr` for *any* driver's mandatory PQ named
curve, not just the NVIDIA CSC0LUT/CSC1LUT stages. The env name says NVIDIA but
the code is generic. Acceptable today (default unchanged; path gated behind the
patch-0013+ opt-in), but a one-line comment scoping it to the NVIDIA Full graph
prevents future confusion if another mandatory graph appears.

### 3. Unit suite cannot exercise the 1.0 path — NIT

Patch 0016's numerical test (`autotests/drm/mockDrmTest.cpp`) uses its own
`TestColorOp` hardcoded to `TransferFunction(PerceptualQuantizer, 0, 125)`, so
the suite stays green under both env values by construction. Acceptable for a
mock, but the investigation doc should state that a green suite is never
evidence about the hardware convention.

### 4. Double blank line — NIT

Left where `namedTransferFunctionScale()` was removed (~`drm_colorop.cpp:1248`).

## Notes

- `tests/test_csc_pq_scale.py` asserts on patch text rather than compiled
  behavior — brittle, but it locks in the critical invariants: default 125,
  bypassable curves always 125, every scaling site routed through the helper.
- Latency accounting: no measurable cost on any rendering or scheduling path;
  the only runtime work is a cached first-call env read during pipeline fitting.

## Verdict

Sound design, safe default, internally consistent with patch 0016's
compensation. **Block on finding 1** (the warning) before running the decisive
experiment; findings 2–4 can ride along.
